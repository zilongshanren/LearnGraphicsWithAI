# Q: 为什么 `(fragCoord - 0.5 * iResolution.xy) / iResolution.y` 可以算出 UV？射线方向为什么是 UV 的方向？

## A: UV 坐标计算

`uv = (fragCoord - 0.5 * iResolution.xy) / iResolution.y` 做了三件事：

### 1. `fragCoord` — 原始像素坐标

ShaderToy 给的像素坐标，左下 (0,0)，右上 (1920,1080)（假设 1080p）：

```
(0, 1080) ────────────── (1920, 1080)
    │                         │
    │      fragCoord          │
    │      范围: 0~1920, 0~1080
    │                         │
(0, 0) ──────────────── (1920, 0)
```

### 2. `- 0.5 * iResolution.xy` — 把原点移到屏幕中心

`0.5 * iResolution.xy` = `(960, 540)`，减去它把坐标系原点从左下角挪到屏幕正中间：

```
(-960, 540) ──────────── (960, 540)
       │                     │
       │      (0,0)          │
       │       ↑ 现在原点在中心
       │                     │
(-960,-540) ──────────── (960,-540)
```

**为什么要移到中心？** 因为摄像机看向正前方，屏幕中心应该是 (0,0)——射线从中心往正前方射出。

### 3. `/ iResolution.y` — 归一化 + 修正宽高比

除以 `iResolution.y`（= 1080），把坐标范围从几百上千缩到大约 -1 到 1：

```
(-0.89, 0.5) ──────────── (0.89, 0.5)
       │                       │
       │       (0,0)           │
       │                       │
(-0.89,-0.5) ──────────── (0.89,-0.5)
```

**关键：为什么只除以 y 而不是分别除以 x 和 y？**

- 如果分别除（`/ iResolution.xy`），x 和 y 范围都是 -0.5 到 0.5，**但一个圆会被拉扁成椭圆**，因为屏幕不是正方形
- 只除以 y，Y 方向固定 -0.5 到 0.5，X 方向按实际宽高比伸展（1920/1080/2 ≈ 0.89），**圆还是圆**

## A: 射线方向

`rayDir = normalize(vec3(uv, 1.0))` 的直觉：

想象摄像机前方 1 个单位远处有一块"虚拟屏幕"。每个像素的 uv 就是它在这块屏幕上的偏移位置。`vec3(uv.x, uv.y, 1.0)` = 从摄像机指向该像素的方向。

```
        虚拟屏幕（距离摄像机 1.0 单位远）
        ┌───────────────────┐
        │  ·  ·  ·  ·  ·   │
        │  ·  ·  ·  ·  ·   │  ← 每个 · 是一个像素
        │  ·  ·  ✦  ·  ·   │  ← ✦ = 屏幕中心 (uv = 0,0)
        │  ·  ·  ·  ·  ·   │
        │  ·  ·  ·  ·  ·   │
        └───────────────────┘
              ↑ z = 1.0
              │
              │ 距离 = 1.0（焦距）
              │
         📷 摄像机 (rayOrigin)
              z = 0
```

具体例子：

| 像素位置 | uv | vec3(uv, 1.0) | normalize 后 | 方向 |
|----------|-----|---------------|-------------|------|
| 屏幕中心 | (0, 0) | (0, 0, 1) | (0, 0, 1) | 正前方 |
| 右上角 | (0.89, 0.5) | (0.89, 0.5, 1) | ≈(0.63, 0.35, 0.7) | 偏右上 |
| 左下角 | (-0.89, -0.5) | (-0.89, -0.5, 1) | ≈(-0.63, -0.35, 0.7) | 偏左下 |

边缘像素偏离正前方的角度更大 → 这就是**透视投影**的本质（近大远小）。

### 那个 `1.0` 本质上是焦距

```
焦距 = 0.5 → 广角（射线散得更开，鱼眼感）
焦距 = 1.0 → 标准视角（≈ 90°）
焦距 = 2.0 → 长焦（射线更集中，望远镜感）
```

在 Step 3 里用了 `1.8`——稍窄的视角，让画面更"电影感"。

**验证方式**：在 ShaderToy 里把 `1.0` 改成 `0.3` 或 `3.0`，立刻能感受到焦距变化。这就是"改参数 → 预测 → 验证"的学习循环。
