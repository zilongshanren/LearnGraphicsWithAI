# Q: 为什么 `(fragCoord - 0.5 * iResolution.xy) / iResolution.y` 可以算出 UV？射线方向为什么是 UV 的方向？

## A: UV 坐标计算

`uv = (fragCoord - 0.5 * iResolution.xy) / iResolution.y` 做了三件事：

1. **`fragCoord`**：ShaderToy 给的像素坐标，左下 (0,0)，右上 (1920,1080)
2. **`- 0.5 * iResolution.xy`**：把原点从左下角移到屏幕中心，因为摄像机看向正前方，中心应是 (0,0)
3. **`/ iResolution.y`**：归一化到约 -1~1 范围。只除以 y（而不是分别除以 xy），是为了**保持宽高比**——否则圆会被拉扁成椭圆

## A: 射线方向

`rayDir = normalize(vec3(uv, 1.0))` 的直觉：

想象摄像机前方 1 个单位远处有一块"虚拟屏幕"。每个像素的 uv 就是它在这块屏幕上的偏移位置。`vec3(uv.x, uv.y, 1.0)` = 从摄像机指向该像素的方向。

- 屏幕中心 uv=(0,0) → 射线方向 (0,0,1) → 正前方
- 屏幕右上 uv=(0.89,0.5) → 射线偏向右上方
- 边缘像素偏离角度大 → 这就是透视投影（近大远小）

**那个 `1.0` 本质上是焦距**：
- 0.5 → 广角（鱼眼感）
- 1.0 → 标准（~90° 视角）
- 2.0 → 长焦（望远镜感）

可以在 ShaderToy 里直接改这个数字来感受差异。
