# Q: 为什么 calcNormal 用"微小偏移法"可以算出正确的法线？

## A: 三层理解

### 第一层：法线是什么

法线 = 表面在某点"朝外"的方向。光照需要法线：表面朝向光源 → 亮，背对光源 → 暗。

```
            ↗ 法线（指向"外面"）
           ╱
      ────●──────  表面
          p
```

### 第二层：为什么 SDF 的梯度就是法线

SDF(p) = 点 p 离表面的距离。正数在外面，负数在里面。

在表面附近，SDF 值增长最快的方向 = 远离表面向外 = 法线方向。

```
           SDF = 0.3
          ↗
        SDF = 0.2
       ↗
     SDF = 0.1
    ↗
───●──────────── 表面 (SDF = 0)
   p
  SDF = -0.1
```

数学上叫**梯度（gradient）**：函数值变化最快的方向。

### 第三层：代码怎么算梯度

梯度有三个分量（x, y, z），每个分量 = "沿这个轴 SDF 变化有多快"。

`e = vec2(0.001, 0.0)`，利用 swizzle 构造三个轴的偏移：

```
e.xyy = (0.001, 0, 0)  → x 方向偏移
e.yxy = (0, 0.001, 0)  → y 方向偏移
e.yyx = (0, 0, 0.001)  → z 方向偏移
```

以 x 分量为例：

```
scene(p + (0.001, 0, 0)).x - scene(p - (0.001, 0, 0)).x
```

把 p 沿 x 轴往右挪一点测 SDF，往左挪一点测 SDF，相减 = x 方向的变化率。

```
         p-e         p         p+e
          ·─────────●─────────·
          │                   │
     SDF = 0.48          SDF = 0.52
          │                   │
          └───── 差值 = 0.04 ─┘
               x 方向变化率
```

### 具体例子：球体顶部

球心 (0, 0.5, 0)，半径 0.5。p = (0, 1.0, 0)——球体正上方。

```
                ↑ 法线应该指向正上方 (0, 1, 0)
                │
                ● p = (0, 1.0, 0)
        ╭───────────────╮
       ╱                 ╲
      │    球心(0,0.5,0)   │
       ╲                 ╱
        ╰───────────────╯
```

```
x 分量: sdSphere((0.001, 1, 0)) - sdSphere((-0.001, 1, 0))
      = 对称 = 0                        ← x 方向没有变化

y 分量: sdSphere((0, 1.001, 0)) - sdSphere((0, 0.999, 0))
      = 0.001 - (-0.001) = 0.002        ← y 方向变化最大！

z 分量: 对称 = 0                         ← z 方向没有变化
```

结果：normalize(0, 0.002, 0) = **(0, 1, 0)** → 正上方 ✅

### 球体侧面的例子

p = (0.5, 0.5, 0)——球体正右方。

```
x 分量 = 0.002    ← x 方向变化大
y 分量 = 0        ← 对称
z 分量 = 0        ← 对称
```

结果：normalize(0.002, 0, 0) = **(1, 0, 0)** → 正右方 ✅

### 为什么叫"中心差分法"

```
前向差分:  f'(x) ≈ (f(x+e) - f(x)) / e        ← 精度低
中心差分:  f'(x) ≈ (f(x+e) - f(x-e)) / 2e     ← 精度高（误差 e² 级别）
```

代码用中心差分。没有除以 2e 是因为最后 normalize 只关心方向不关心大小。

### 为什么不用解析公式

球体法线可以直接算 `normalize(p - center)`。但微小偏移法对**任意 SDF 都有效**——不管场景多复杂（布尔运算、smooth union、空间扭曲），同一个 calcNormal 都能正确工作。

**这是 SDF 方法论的优雅之处：一套通用代码，搞定所有形状的法线。**
