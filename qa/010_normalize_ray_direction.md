# Q: uv 不是代表每个屏幕像素吗？`vec3(uv, 1.0)` 为什么不是每个像素往 z+1 方向前进？

## A: normalize 之前，你的理解完全正确

`vec3(uv, 1.0)` 确实是"每个像素点往 z+1 方向走"：

```
像素 A: uv = (0, 0)      → vec3(0,    0,   1.0)
像素 B: uv = (0.5, 0)    → vec3(0.5,  0,   1.0)
像素 C: uv = (0.89, 0.5) → vec3(0.89, 0.5, 1.0)
```

这三个向量的终点落在 z=1 的平面上不同位置——方向不同，但都朝 z+1 走。

## normalize 改变了什么

`normalize` 把向量长度压到 1，方向不变：

```
normalize(0,    0,   1.0) = (0,    0,    1.0)   长度本来就是 1，不变
normalize(0.5,  0,   1.0) = (0.45, 0,    0.89)  长度从 1.12 压到 1
normalize(0.89, 0.5, 1.0) = (0.63, 0.35, 0.7)   长度从 1.14 压到 1
```

方向没变，但每条射线走相同步数时到达的位置不同了：

```
normalize 之前（方向正确，步长不一致）：

    z=1 平面
    ┌──────────────┐
    │  B      C    │  ← 走 1 步后都落在 z=1 平面
    │     A        │     但 A 走了 1.0，C 走了 1.14（长度不同！）
    └──────────────┘

normalize 之后（方向相同，步长统一为 1）：

         C  ← 走 1 步后落在各自方向上 1.0 距离处
       ↗
    📷──→ A
       ↘
         B

    三条射线长度都是 1.0
```

## 为什么 Ray Marching 必须 normalize

射线位置计算：

```glsl
vec3 currentPos = rayOrigin + rayDir * totalDist;
```

`totalDist` 是累计步进距离。如果 `rayDir` 长度不是 1，`totalDist` 就不等于真实距离——而 SDF 返回的是真实距离，两者单位不一致，步进就会出错：

```
rayDir 未归一化（长度 1.14）：
  走 totalDist = 1.0 → 实际移动了 1.14 个单位
  SDF 说"还有 1.0 才到物体" → 实际走了 1.14 → 穿模！❌

rayDir 归一化后（长度 1.0）：
  走 totalDist = 1.0 → 实际移动了 1.0 个单位
  SDF 说"还有 1.0" → 走 1.0 → 恰好安全 ✅
```

## 一句话总结

`vec3(uv, 1.0)` 给了正确的方向（从摄像机指向每个屏幕像素）；`normalize` 只是把长度统一成 1，让步进距离与 SDF 距离单位一致。**方向没有任何改变。**
