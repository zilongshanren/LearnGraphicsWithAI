# Q: 为什么"步进距离和 SDF 距离用同一把尺子"就会有透视效果？

## A: 透视效果和 normalize 是两件独立的事

我之前的解释把它们混在一起了，重新澄清：

### 透视效果来自哪里

透视效果**只来自射线方向不同**，和 normalize 无关。

边缘的射线是斜着出去的，斜射线走同样的距离，在深度方向（z）上走得更少：

```
中心射线（垂直向前）：
    📷 ──────────────────→  走 10 步，z 方向推进了 10

边缘射线（斜向右）：
    📷 ──────────────────↗  走 10 步，z 方向只推进了 7
                             x 方向推进了 7
```

同一个物体，被边缘射线打到时射线已经走了更多步——在屏幕上看起来更小更远，这就是透视。

**这个斜角从哪来的？就是 `vec3(uv, 1.0)` 里的 `uv`：**
- 中心像素 uv=(0,0) → 方向 (0,0,1) → 垂直向前
- 边缘像素 uv=(0.89,0.5) → 方向偏斜 → 透视产生

### 用极端例子感受

场景里有一堵墙在 z=5 处，屏幕只有三个像素：左、中、右：

```
          墙 (z=5)
           │
左射线  ↗  │  斜着打到墙，命中点 x 偏移大
           │
中射线  →  │  垂直打到墙，命中点 (0,0,5)
           │
右射线  ↘  │  斜着打到墙，命中点 x 偏移大
           │
📷
```

三条射线命中点的 x 坐标不同——墙呈现"中间近、两边远"的透视感。**这就是透视，和 normalize 完全无关。**

### normalize 解决的是另一个问题

normalize 解决的是**步进计算的正确性**，和透视没有关系：

```
没有 normalize 时：

中心射线 direction = (0, 0, 1)，    长度 = 1.0
边缘射线 direction = (0.89, 0.5, 1)，长度 = 1.14

SDF 说"离物体还有 0.5"：
  中心射线：走 0.5 步 → 实际移动 0.5 × 1.0  = 0.5  ✅
  边缘射线：走 0.5 步 → 实际移动 0.5 × 1.14 = 0.57 ❌ 走多了，穿模
```

normalize 后两条射线长度都是 1，步进距离和 SDF 距离单位一致，不穿模。
**但透视在 normalize 之前就已经存在了——方向斜了就有透视，和长度无关。**

### 总结

```
透视效果 ← 来自 vec3(uv, 1.0) 中的 uv
             uv 不为零 → 射线方向斜 → 透视

normalize  ← 来自步进计算的工程需求
             长度=1 → 步进距离与 SDF 距离单位一致 → 不穿模

两者独立，normalize 不产生透视，也不破坏透视。
```
